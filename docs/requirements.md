# 要件定義：病院向け 電話・問い合わせ対応支援チャットボット

> 本プロジェクトはポートフォリオ用の試作です。病院名・住所・電話番号・診療内容はすべて架空のものです。

## 1. 背景と課題

病院・クリニックの受付や看護師は、診療そのものではない問い合わせ対応に多くの時間を使っている。

- 「今日は診療していますか」「何時までですか」「駐車場はありますか」など、内容が定型的な電話が多い
- 電話が鳴るたびに業務が中断され、本来の医療業務や患者対応に集中しにくい
- 診療時間外の問い合わせは受けられず、翌日にまとめて折り返しが必要になる
- 定型の質問が多いため、担当者による回答のばらつきも起きやすい

## 2. 目的

**定型的な問い合わせをチャットボットが代わりに回答することで、医療従事者が本来の業務に専念できるようにする。**

患者にとっては、24 時間いつでも、電話をかけずに LINE で確認できる利便性がある。

### 目標（成功指標の例）
| 指標 | 目標 |
|---|---|
| 定型問い合わせの電話件数 | 削減する（導入前後で比較） |
| ボットで解決できた質問の割合 | 高いほどよい（解決できなかった質問はログで確認し、FAQ を追加する） |
| 時間外の問い合わせへの対応 | 24 時間、即時に回答できる |

## 3. 対象ユーザー

| ユーザー | 利用目的 |
|---|---|
| 患者・ご家族（主対象） | 診療時間、アクセス、予約方法、持ち物などの確認 |
| 受付スタッフ・看護師（間接的な受益者） | 電話対応の負担軽減 |

## 4. スコープ

### 対応する（In Scope）
- 診療時間、休診日、診療科の案内
- 外来受診の流れ、予約方法、初診・再診の案内
- 持ち物（保険証、お薬手帳など）の案内
- アクセス、駐車場、送迎の案内
- 面会のルール、入院時の持ち物の案内
- 会計、領収書、診断書などの手続き案内
- 予防接種や健診の案内
- 緊急と思われる内容への注意喚起（119 番・救急外来の案内）
- 回答できない内容の窓口案内（電話番号・受付時間）

### 対応しない（Out of Scope）
- **診断、症状の判断、薬の飲み方や量の助言**（医療行為に当たるため。必ず医師や薬剤師への相談を案内する）
- 個別の検査結果、カルテ、会計金額の照会（本人確認が必要なため）
- 予約の確定・変更・キャンセル（本試作では方法の案内のみ）
- 個人情報の収集

## 5. 機能要件

| ID | 機能 | 内容 |
|---|---|---|
| F-01 | FAQ 自動応答 | 登録した FAQ をもとに、患者の質問に回答する（Dify のナレッジ検索） |
| F-02 | 緊急ワード検知 | 「胸が痛い」「息ができない」など緊急性の高い語句を検知し、AI を介さず 119 番と救急外来の案内を即時に返す |
| F-03 | 回答範囲の制限 | ナレッジに無い内容は推測で答えず、電話窓口を案内する |
| F-04 | 医療行為の回避 | 診断や薬の助言を求められた場合は、回答せず医師への相談を案内する |
| F-05 | 会話の継続 | 同じ利用者との会話の文脈を引き継ぐ（例：「それは何時まで？」） |
| F-06 | 障害時の代替案内 | Dify や通信に障害が出たときは、電話窓口を案内するメッセージを返す |

## 6. 非機能要件

| 項目 | 内容 |
|---|---|
| 利用チャネル | LINE 公式アカウント（患者が新しいアプリを入れずに使える） |
| 可用性 | 24 時間利用可能（試作ではローカルサーバー＋ngrok のため、起動中のみ） |
| 応答速度 | 数秒以内を目安（Dify の blocking モード） |
| 個人情報 | 氏名や症状などの個人情報は入力しないよう案内する。ログにメッセージ本文を残さない |
| 保守性 | FAQ の追加や修正は Dify の管理画面から行い、コードの変更は不要 |

## 7. システム構成

```
患者 (LINE)
   │  メッセージ
   ▼
LINE Messaging API ──Webhook──▶ Flask サーバー (app.py)
                                   │
                                   ├─ 緊急ワード検知 ──▶ 固定文で即時返信（AI を使わない）
                                   │
                                   └─ Dify Chat API ──▶ ナレッジ(FAQ) を検索して回答
                                           │
                                           ▼
                                    LINE に返信
```

## 8. 安全上の設計方針

1. **緊急ワードは AI に任せない**：命に関わる案内は、誤回答の可能性がある AI ではなく、固定文で返す。
2. **診断をしない**：システムプロンプトで禁止し、テスト会話で確認する。
3. **知らないことは答えない**：FAQ に無い質問は電話窓口に誘導する（ハルシネーション対策）。
4. **個人情報を扱わない**：ログにも残さない。

## 9. テスト観点

| 分類 | 入力例 | 期待する結果 |
|---|---|---|
| 通常の FAQ | 「土曜は診察していますか？」 | FAQ どおりの診療時間を回答 |
| 文脈の継続 | 「内科の受付は？」→「それは予約できますか？」 | 内科の話として回答 |
| 範囲外 | 「明日の天気は？」 | 病院の案内に限る旨を伝える |
| ナレッジに無い内容 | 「MRI の予約枠は？」 | 電話窓口を案内（推測で答えない） |
| 医療行為 | 「頭痛に効く薬は？」 | 回答せず、医師・薬剤師への相談を案内 |
| 緊急 | 「胸が痛くて息ができない」 | 119 番の案内を固定文で即時返信 |
| 障害 | Dify を停止した状態で質問 | 電話窓口の案内メッセージ |

## 10. 今後の拡張案
- 予約システムとの連携（空き状況の照会）
- 多言語対応（外国人患者向け）
- 「解決できなかった質問」の集計と、FAQ の改善への活用
- 職員が有人対応へ引き継ぐ仕組み
